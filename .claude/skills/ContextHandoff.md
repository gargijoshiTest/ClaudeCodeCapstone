# Context Handoff Skill

This skill defines the **standard state payload** that every SDLC agent must emit at the end of its phase and verify at the start of the next. It prevents agents from proceeding with missing or ambiguous upstream context.

---

## When to Emit a Handoff

Emit a handoff block whenever you:
- Finish your final phase and commit your output document
- Are interrupted mid-task and need to hand off to a continuation
- Are asked to summarise current SDLC state

## Handoff Block Template

Emit this block in a fenced `handoff` code block at the end of your final output:

```handoff
## SDLC Context Handoff
Generated by: <agent-name>
Timestamp: <ISO-8601 date>
Story: <User Story title — from requirements.md or JIRA>
Ticket: <JIRA key or "manual">

### Documents Available
| Doc | Path | Status |
|---|---|---|
| Requirements | docs/requirements.md | ✅ Complete / ⚠️ Partial / ❌ Missing |
| Architecture | docs/architecture.md | ✅ Complete / ⚠️ Partial / ❌ Missing |
| Design Review | docs/design-review.md | ✅ Complete / ⚠️ Partial / ❌ Missing |
| Impl Plan | docs/impl-plan.md | ✅ Complete / ⚠️ Partial / ❌ Missing |
| Code Review | docs/code-review.md | ✅ Complete / ⚠️ Partial / ❌ Missing |
| QA Report | docs/qa-report.md | ✅ Complete / ⚠️ Partial / ❌ Missing |

### Decisions in Force
List every DD-XX agreed in docs/design-review.md:
- DD-01: <decision> — rationale: <why>
- DD-02: <decision> — rationale: <why>

### Acceptance Criteria Status
| AC | Covered by test? | Notes |
|---|---|---|
| AC-01 | ✅ Yes / ❌ No | <test name or gap> |

### Open Items
| ID | Item | Owner | Blocking? |
|---|---|---|---|
| OQ-01 | <question> | TBD | Yes / No |

### Recommended Next Agent
<agent-name> — reason: <why this agent should run next>

### Blockers for Next Agent
- <list any blockers the next agent must resolve first, or "None">
```

---

## How to Verify an Incoming Handoff

At the start of your phase, check:

1. **All required upstream documents exist** — if a doc is marked ❌ Missing, stop and tell the user which agent must run first.
2. **All DD-XX decisions are known** — if the design review has not been run, do not invent design decisions.
3. **No blocking open items** — if a blocker is listed for your phase, resolve it before proceeding.

If any check fails, emit this message and halt:

> "Incoming context is incomplete. The following items must be resolved before I can proceed: [list]. Please run [agent-name] first."

## Minimum Context per Agent

| Agent | Minimum Required |
|---|---|
| solutionArchitect | docs/requirements.md (✅ Complete) |
| designReviewer | docs/architecture.md (✅ Complete) + docs/requirements.md |
| developer | docs/architecture.md + docs/design-review.md (✅ Complete) |
| codeReviewer | All source files written + docs/requirements.md |
| qaEngineer | All source files + docs/requirements.md + docs/impl-plan.md |
| prCreator | docs/code-review.md + docs/qa-report.md (QA verdict = PASS or APPROVED) |

---

## Guardrails

- **Never fabricate handoff state.** Only emit what is actually present on disk.
- **Never skip the incoming-context check.** An agent that proceeds without upstream context will produce incorrect output.
- **Timestamp every handoff.** Future agents use it to detect stale context.
- **Re-emit the handoff if you update a document mid-phase** — the state must reflect the latest disk state.
